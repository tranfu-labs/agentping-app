先做这 4 步

别先重启软件，先判断是哪一段断了。

  1. 看官方状态。如果 OpenAI 或 Claude 官方正在异常，先不要折腾本地网络。
  2. 看 Ageng网络医生。绿色可继续，黄色跑短任务，红色先换节点或查代理。
  3. 看出口地区。同一个 VPN 在线，不代表当前出口适合跑 Agent。
  4. 按工具处理。Codex、Claude Code、Cursor 的失败表现不一样。

先按颜色决定下一步

绿色

网络大概率可用。若 Agent 仍不动，再看任务长度、工具进程或模型响应。

黄色

短任务可以试，长任务先换更稳定节点，避免中途失败。

红色

先暂停 Agent，不要继续堆上下文。按提示换节点或查代理。

Codex

Codex 一直 Working，几分钟后才恢复

你看到的是 Codex 还在转，但没有新输出。公开问题记录里，确实有人遇到长时间等待后才重试恢复的情况。

先判断

如果 Ageng网络医生里 OpenAI 是红色，先处理网络。如果 OpenAI 是绿色，但 Codex 卡住时间很固定，可能是长连接已经断了，工具还没及时发现。

怎么做

先复制 Ageng网络医生诊断报告，再换一个更稳定、延迟更低的出口节点。长任务建议拆成几段跑，避免一次卡住损失整段上下文。

Codex

Codex 提示 stream disconnected

这类问题通常不是“模型不会答”，而是流式连接中途断了。代理节点、公司网关、浏览器式代理都可能影响长连接。

先判断

看 Ageng网络医生是否显示黄色或红色，再看出口地区是否刚切换过。如果短请求正常、长任务断流，重点怀疑节点稳定性。

怎么做

优先换到团队标记为“长任务稳定”的节点；如果只是临时使用，先暂停大规模编辑任务，等链路稳定后继续。

Claude Code

Claude Code 一直没输出：先看 Anthropic 是否红

Claude Code 没有输出，不一定是软件坏了。很多时候是 Anthropic 链路不可用，Agent 还在等网络返回。

先判断

如果 Anthropic 是红色，而 OpenAI 是绿色，更可能是当前出口节点不适合访问 Claude。此时优先换节点，不要马上重启工具。

怎么做

换节点后重新跑 Ageng网络医生。Anthropic 回到绿色再继续；如果仍然无响应，再考虑任务太长、工具进程异常或 Claude 官方服务异常。

Claude Code

Claude Code 报超时、fetch failed、ECONNRESET

Claude 官方文档把 Unable to connect、ECONNRESET、ETIMEDOUT、fetch failed 都归到网络连接类问题。

先判断

不要只看浏览器能不能打开 Claude 网页。Claude Code 访问的是 API 链路，终端环境、代理变量、证书和防火墙都会影响它。

怎么做

先看 Ageng网络医生的 Anthropic 结果。如果是红色，换节点；如果是绿色但 Claude Code 报错，检查终端是否继承了代理，或是否有旧 VPN 残留路由。

Cursor

Cursor 连接失败或反复 Reconnecting

Cursor 的 AI 功能依赖后端服务和流式返回。社区里高频出现的排查方向是网络诊断、代理、HTTP/2、VPN 和防火墙。

先判断

先跑 Cursor 设置里的网络诊断，再看 Ageng网络医生的 OpenAI 和 Anthropic 是否正常。如果模型切换后才失败，要把模型服务商也纳入判断。

怎么做

如果诊断提示连接失败，先换稳定节点；如果只在某些网络下失败，可以尝试关闭 HTTP/2 兼容问题或重新允许 Cursor 通过防火墙。

Cursor

Cursor 还在走已关闭的本地代理

有用户反馈 Cursor 仍然尝试连接 127.0.0.1:10809，导致 ECONNRESET。这个现象很像“代理客户端关了，但软件还记着旧代理”。

先判断

如果代理客户端已经关闭，但 Cursor 诊断里还出现本地端口，优先怀疑系统代理、软件缓存或启动参数残留。

怎么做

先完全退出 Cursor 和代理客户端，再检查系统代理设置。团队环境下建议统一使用 TUN 或明确的代理入口，减少每个软件各自缓存代理的情况。

链路差异

OpenAI 能用，Claude 不行：不是一条链路

OpenAI 能访问，不代表 Anthropic 也能访问。它们使用不同域名、不同服务端入口，也可能被不同出口策略影响。

先判断

如果只有 Anthropic 异常，优先判断为节点出口问题、代理规则问题或 Anthropic 服务侧问题。

怎么做

不要用“浏览器能打开某个网站”来判断 Agent API 链路一定正常。用 Ageng网络医生看对应服务，再决定换节点还是查官方状态。

Cursor

Cursor 换模型后表现不一样：正常吗？

正常。Cursor 里不同模型可能来自不同服务商。你切换模型时，实际访问的接口、域名、出口策略都可能变化。

先判断

OpenAI 模型可用，不代表 Anthropic 模型也可用；自定义 API 又可能走另一套域名和代理规则。

怎么做

遇到这种情况，先用 Ageng网络医生看对应链路，再决定是换模型、换节点，还是调整本地代理规则。

VPN 节点

VPN 显示在线，但 Agent 还是卡

代理客户端显示在线，只说明它和节点之间可能连通。Agent 真正需要的是从本机到 API 服务之间的完整链路稳定。

先判断

共享人数多、出口质量差、抖动高、分流规则没命中，都会让 Agent 长任务卡住。

怎么做

Ageng网络医生要看的不是“节点在线”，而是“Agent 需要访问的接口是否真的可用”。黄色适合短任务，长任务尽量等绿色。

团队网络

团队稳定 VPN / VPS 搭建流程

这篇整理给团队管理员看：目标不是“能翻出去”，而是让 Codex、Claude Code、Cursor 长任务更稳定。

1. 选地区。

优先选日本、新加坡、香港、美国西海岸中实际延迟低、出口干净的地区，不只看价格。

2. 准备 VPS。

每个节点单独记录供应商、地区、到期时间、用途和负责人，避免节点坏了没人知道。

3. 部署网关。

团队内部统一协议、端口和订阅格式，避免每个人自己乱配导致排查困难。

4. 分发订阅。

把个人节点、团队 VPS、备用节点分组；长任务节点单独标记，减少误用。

5. 导入 Clash。

使用 Clash Verge Rev 等仍在维护的软件，导入订阅后检查规则、TUN 和系统代理是否按预期工作。

6. 用 Ageng网络医生验收。

节点上线后不要只测网页。连续测试 OpenAI、Anthropic、出口地区和延迟，稳定后再开放给团队。

建议保留一个“只给 AI Agent 用”的策略组。浏览网页和跑 Agent 分开，可以减少长任务被临时切节点打断。

工作流

跑长任务前：先花 30 秒自检

长任务最怕跑到一半卡住。开始前先确认链路，可以少浪费很多上下文。

先判断

OpenAI 和 Anthropic 都是绿色，再开始需要长时间执行的任务；如果显示黄色，优先跑短任务或先换节点。

怎么做

如果显示红色，先排查网络，不要直接把复杂任务交给 Agent。团队成员可以把诊断报告发给管理员处理。

团队协作

出问题时，怎么把信息发给管理员

“卡了”“不能用”很难排查。最好把问题变成可判断的信息。

建议带上

工具名称、当时颜色、OpenAI/Anthropic 延迟、出口国家或地区、代理客户端、报错文字、发生时间。

怎么做

在 Ageng网络医生菜单里复制诊断报告，直接发到团队群。管理员可以更快判断是个人设备、节点、规则还是官方服务问题。
